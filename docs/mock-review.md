- Definite failures show "Nothing has been deleted" (24361–24363). Not-installed RPC (PGRST202/404) is a definite failure, so a missing backend never produces a false success.
- Old `sendDataEmail` / "Email Data & Delete" / `confirm('Type your email…')` are gone (grep: 0).
- UNVERIFIABLE-HERE: whether `delete_my_account.sql` has actually been run in the Supabase project (it lives on `app-store-backend`, not on `app-store`).

### 2d. RevenueCat key handling — PASS with a silent-failure trap
- `native-bridge.js:339` `RC_API_KEY = '__MG_RC_API_KEY__'`; `rcAvailable` requires `/^appl_/` (340). The web copy is never substituted (prepare-www writes only into `www/`, `prepare-www.mjs:55–66`). PASS for "never reaches the web".
- Trap 1: the substitution regex `/^appl_[A-Za-z]+$/` (`prepare-www.mjs:62`) rejects any key containing a digit. If Max's real key has a digit, the build is produced **with a warning only** and the shipped app has `purchases.available === false`.
- Trap 2: with `available === false`, `isProUnlocked()` returns **true** (23494, comment "no store in this build (e.g. dev)"), so the submitted build has no paywall at all, while Settings shows a permanent "Checking subscription…" (1205, `_renderProStatus` never runs) and "See plans" shows "Subscriptions are not available in this build." (23677). That mismatches the listing and the review notes.
- Fix: accept `[A-Za-z0-9]`, make a missing/placeholder key a hard failure for a release build (env flag in the workflow), and consider locking rather than unlocking when the store is unavailable in native.
